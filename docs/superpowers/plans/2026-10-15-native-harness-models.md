# Native Harness model catalogs and per-run selection

Continue the v3 publication backend using the existing adapter boundary and dispatch pipeline.

## Acceptance
- Catalogs originate in the selected native account/project context; cache and authentication uncertainty remain explicit.
- Explicit selection and native default remain distinct, with model/parameters frozen across start and subsequent messages.
- No global profile/default/credential mutation; no invented model, effort, entitlement or price.
- Each usable installed Harness receives a disposable repository publication run and exact artifact/verification evidence. Unavailable or incompatible native interfaces remain explicit blockers.
- Check official quota after each stage and stop when any readable window has at most 15% remaining.

## Stages
1. Shared StructuredCliAdapter selection snapshot and native read boundary; Cursor account catalog and real publication execution.
2. Qoder CN, Grok and Antigravity native catalogs with supported single-run selection; verify providers sequentially.
3. OpenCode native discovery and execution, plus capability evidence for remaining unavailable/incompatible Harnesses.
4. Full regression, independent review, durable verification notes and final quota checkpoint.

## Verification
Targeted adapter/controller regressions first, then pnpm check. Native evidence must distinguish requested model from runtime-reported model and must include receipt, execution selection, actual worktree artifacts and verification outcome. Read-only model queries are bounded and do not launch agent tasks.
