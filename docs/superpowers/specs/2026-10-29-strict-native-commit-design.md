## Intent and limits

A currently qualified HUMAN-return native snapshot proof may deliver its exact verified tree through the existing local Git owner, then finish Run COMPLETE/Task REVIEW. Success must identify the actual source authored commit (not the synthetic verification commit), preserve native permission and factual command uncertainty independently, and not repeat a known send after later metadata failure. Only local commit is added. PR/push/SCM, remote snapshot commit, bound completed canonical acceptance, provider/native exclusion capability, physical stop, formal release Gates and original49 full purposes remain separate. No real user/provider/repository mutation is part of development validation; use owned disposable repositories and real owned children.

## Approaches and choice

1. Reuse ordinary LocalGitDelivery.commit directly: rejected because legacy run/generation receipt cannot distinguish successive HUMAN proofs and ordinary quiet success/clean branch is not expected tree/single parent proof.
2. Implement another Git/native coordinator: rejected because it duplicates ProcessManager ownership, G3a command journal and permission boundaries.
3. Extend the existing LocalGitDelivery with one private proof-scoped operation and shared context logic; integrate it at the existing Service delivery branch. Chosen by root because both factual mutation and current proof authority retain their real owners. Existing Git CLI, ProcessManager, WorkspaceManager and VerificationSnapshots are the mature implementations reused. No third-party code/dependency is incorporated; another Git library would not supply these project-specific control/receipt semantics.

## Factual classification and recovery

The owner retains attempt state: before any possible mutation it is not-sent; once a stage/commit SENDING boundary is reached it is conservatively unknown; only after full authored/no-change observation it is observed. Related old uncertainty overrides not-sent. snapshotCommitOutcome validates the exact input/associated facts/parent and current owner memory or fully validated COMPLETE; it must not turn missing/changed receipt facts after a send into not-sent. Storage/parse failures remain unavailable/unknown or original errors, never successful classification. No merely SETTLED nonzero/failed stage is observed. A new instance treats PENDING as unknown; no automatic across-restart reconciliation.

Same-instance fully observed memory can repair its still-matching PENDING metadata without new stage/commit only after current permission, retained snapshot, actual authored source tuple and command-fact validation. Persisted same-proof COMPLETE restart recovery does the same physical/current qualification and returns the old result without reauthoring. In both cases skip obsolete pre-stage HEAD/content assertions but keep actual post-commit context/tree/parent/branch/status/manifest qualification. Changed input/proof/current epoch cannot reuse that outcome. Never clear an older NativeInteractions unknown row or infer permission from this factual classifier.
