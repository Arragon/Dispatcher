# Agent 账号模型目录、默认模型、任务选择与运行用量

日期：2026-10-04。状态：设计待审阅，尚未实现。

## 用户目标与范围

独立的「发布任务」页面通过系统目录选择器选择项目目录，再选择 Agent
账号、执行模型，输入任务并开始执行。任务及当前运行统一显示在既有
「任务与运行」页面。本设计定义其中的模型管理、执行选择和运行用量；目录选择、本地
任务创建和结果交付沿用该页面的整体需求，不在这里重新设计执行目录策略。

已确认要求：

1. 每个 Agent 账号有一个可设置的默认模型。同类 Agent 的不同账号分别设置。
2. Dispatcher 主动获取该账号的模型目录；上游提供时显示价格、倍率、免费和
   优惠信息。
3. 发布任务时从该目录选择具体模型；未另选时使用账号默认模型。
4. 已启动任务保留启动时的选择，不随账号默认值或目录刷新改变。
5. 倍率和优惠以该账号 CLI 的当前模型查询结果为准，不读取平台静态价格
   文件或用公开报价补齐；选择模型和开始执行前都重新查询。
6. harness 能提供时，实时展示输入、输出、缓存命中等 token 用量，以及
   额度消耗、剩余额度和重置时间。更新频率与统计范围以原生数据为准。

当前架构要求受管 worktree 执行；选择项目目录不自动代表允许在原目录修改。
本设计保留这一边界。普通目录和在原目录执行需要另行明确执行策略。

## 当前实现与需要补齐的边界

- `AgentProfileConfig.settings.model` 已保存默认模型字符串，但账号查询没有
  返回默认模型，UI 没有模型目录。
- `AgentAdapter.start`、Scheduler dispatch 和 HTTP `TaskDispatchBody` 没有
  单次模型选择字段。CLI 参数来自适配器实例的账号配置。
- Qoder 的登录探测已执行 `--list-models`，但没有保留或规范化目录。
- 大部分 CLI 接受模型参数；ZCode 当前明确拒绝 Dispatcher 的模型字段，
  Kiro 当前把模型字段传给 `--agent`。这些行为不能作为模型选择可用的证明。
- `Run.model` 区分配置选择和运行上报；应保留这种证据区别。
- 已有 Run token 字段和 Codex 最新完成回合计量，但不是通用的运行累计。
  部分适配器已返回 consumed / remaining；Controller 的 ResourceSnapshot
  目前仅保留状态、原因和重置时间，需要独立保留数值计量和单位。

复用已安装 Agent 的原生只读接口和现有 Adapter、ConfigPlan、Scheduler、
Canonical Task、Fleet、SSE 能力。无需引入统一模型网关，也不为读取模型迁移
现有执行后端。调用约定以安装版本的帮助、原生协议和实测输出为准。

## 用户界面

### Agent 账号页面

账号表格增加「默认模型」列。账号详情增加模型区域：搜索、刷新目录、默认
模型选择和保存。每行显示模型名称、原生 ID、来源平台、计费信息和选择能力。

每次打开详情主动重新获取目录，另提供手动刷新。上次结果仅用于加载期间
展示，标为「上次查询」，不当作当前价格。显示最后成功获取时间和刷新错误。
刷新不会改变默认模型，也不会发起模型推理。

默认模型从该账号的目录选择，通过 ConfigPlan 保存，保留配置版本冲突和
活动账号保护。当前运行导致配置更新被拒绝时明确显示原因，不取消任务。
旧配置的默认模型即使已从目录消失也保留显示，并标为不可选择，要求重选。

### 独立发布任务页面

顺序为项目目录、Agent 账号、模型、任务说明、开始执行。选择账号后加载该
账号在所选项目上下文中的最新目录，默认选中账号默认模型。允许改选目录内
具体模型；每次改选重新查询该模型的信息，改选只影响本次任务。切换账号或
项目重新获取目录，清除之前上下文的模型和计费展示。

模型选项展示有来源的费用标签，例如「Credits 倍率」「免费」「限时优惠」
或「输入 / 输出单价」。价格缺失显示「价格未提供」。如有多种计费维度，
下拉项给出简要标签，选中项下方显示完整单位、条件、来源与更新时间。
这里的例子只是展示格式，不是任何账号的实时报价。

自动路由或分档选项可在上游支持时展示，但明确标为「自动路由」或「模型档位」，
不冒充一个具体模型。实时查询失败时保留上次信息并明确显示刷新失败，
不能使用上次查询结果启动新任务。当前查询成功但 CLI 不提供价格时，
可以选择模型执行，价格显示「CLI 未提供」。
模型访问权限未被上游确认时标为「访问权限未确认」，允许用户主动启动任务；
执行失败按真实原因记录，不自动改用另一个模型。

### 任务与运行页面

显示启动时选定模型、选择来源（账号默认 / 本次指定）、执行端确认的模型
（如有）以及启动时的价格信息。目录更新不得改写历史价格或模型选择。
配置选择和运行上报分别展示；自动路由任务的最终模型只有真实上报时才显示。

任务行显示有统计范围的 token 用量和原生运行消耗；详情展示输入、输出、
缓存读取、缓存写入、缓存命中率（能可靠计算时）、额度消耗、账户剩余额度、
重置时间及最后采集时间。每项缺失独立显示「harness 未提供」，不能显示为零。
账号详情显示账户周期额度；任务详情中的账户指标明确标为账户数据。

## 实时 token 与额度计量

### 原生来源与更新时机

优先消费 harness 的结构化流式用量事件、原生会话状态或额度查询接口。
实时性指收到新上报后尽快持久化并经既有 Fleet/SSE 通知页面；不根据模型
输出字符数、历史平均值或静态价格倍率推测 token 或额度。

适配器必须分别声明 token、缓存、运行消耗和账户额度的读取能力及更新时机。
流式上报即时更新；只有回合结束上报的标为「完成回合后更新」；只有最终结果
的标为「任务结束后提供」。不能用一个 usage 能力标志推断所有字段都存在。
原生只读查询在现有运行推进 / 资源探测边界执行并推送；不新增无界常驻轮询，
查询不启动推理、续写或另一个 Agent 会话。

现有 Codex / Qoder usage 实现等待当前 turn.result，不能直接作为进行中的
实时读取。支持过程用量时由 Adapter 提供当前已收到的事件或非阻塞快照，
Controller 不为读取计量等待整个执行结束，也不自行解析各 provider 输出。

### token 语义

保留输入、输出、缓存读取 / 命中、缓存写入及原生提供的其他细分字段。
每项带计量单位、范围（本回合 / 本次运行 / 当前会话 / 账户周期）、源事件
身份和更新时间，并区分增量事件与累计快照。未提供的细分字段保持缺失。

缓存 token 与输入 / 输出的包含关系由 Adapter 按原生协议明确规范化。
例如当前 Codex 缓存输入包含于输入，不能再加到总 token；其他 harness 的
缓存读写可能采用不同口径。只在总输入及缓存读取的口径可比较且分母大于零
时计算缓存命中率，明确显示按 token 计算；不能冒充原生按请求次数的命中率。
零输入或口径未知时显示命中率未提供。推理 token 等其他字段同样避免重复加总。

累计上游快照采用替换，不逐次相加。回合增量只在原生回合 / 事件身份和范围
可确定时累加；重复事件、重连重放与恢复查询不能重复计费。只有最新回合数据
时继续标为最新回合；完整累计无法证明时显示「已采集部分回合」，不冒充总量。
已结束运行保留最终计量；reroute 和新 attempt 分别记录，旧运行不被覆盖。

### 消耗、余额与计费

运行消耗按原生单位展示，例如 Credits、ACU、货币金额或请求次数。价格倍率
是费率，不能当作已消耗额度；token 数也不能当作账户剩余额度。
上游返回实际运行消耗时按该运行显示；只有账户余额时仅显示账户余额，不能
用账户前后差额归因于某任务，因为同账号可能有其他并行使用。

账户已用 / 剩余 / 总额度和重置时间按上游提供的每个周期分别展示，保留周期
起止、单位和最后上报时间。额度包含关系或总量不明确时不生成已用百分比。
免费 token 和额度消耗为零是不同结论；未知消耗保持缺失。

价格快照与实际消耗分开存储和展示。本范围不自行估算费用；原生上报的
实际消耗按原始单位保存，不用价格倍率推算，也不宣称是最终结算账单。

### 持久化与可靠性

规范化计量绑定 profile、Run、原生 session、generation、attempt 和回合 / 事件
身份。账户周期数据独立按 profile 保存。已有 ResourceSnapshot 继续负责
资源状态和调度，不能用新增数值计量绕过资源阻塞、租约或当前运行校验。

持久化规范化数值、单位、范围、来源、上报 / 采集时间及去重身份，不把原始
输出写入 SQLite。通过既有事件总线和 Fleet 投影更新页面；纯采集心跳不
作为任务执行进展，也不自动清除 stall。数值未变化时不重复发布相同更新。

断线或查询失败保留最后成功数值，显示最后采集时间与连接 / 更新状态，
不把旧数值标为实时，不归零。计量缺失或查询失败不阻断正在执行的任务；
真正的资源耗尽仍走既有 RESOURCE_BLOCKED / WAITING_RESOURCE 路径。

## 模型目录与计费信息

### 账号及项目作用域

目录由适配器在对应账号的原生配置环境中读取。不同账号不共享可用模型结论。
若 Agent 的模型配置取决于项目，则还必须绑定项目的有效配置上下文。
模型条目和价格直接来自该账号 CLI 的只读模型查询输出，或该 CLI 明确提供的
原生模型查询协议。Dispatcher 不直接读取平台静态价格文件、模型缓存文件、
公共价格目录或硬编码倍率，不从这些来源补齐缺失价格。

查询时使用 CLI 已有的原生刷新能力（若有）。重新运行命令不等于上游必然
实时返回：若 CLI 只返回内部缓存且没有刷新或新鲜度证据，须标为「CLI 缓存，
实时性未确认」，不能标为实时价格。非 CLI Agent 仅使用其正式账号模型查询
接口，并如实标明来源，不冒充 CLI 查询结果。

读取只使用固定、允许列出的 CLI 命令或原生 RPC/API，不接受客户端提交的
可执行文件或命令。不给网页返回凭据、账号私有配置目录或原始上游响应。
不复制原生凭据，不通过试用付费推理来自动刷新目录。

统一快照包含账号 ID、Agent/provider、上下文标识、内容版本、获取时间、
来源类型、可选条目和读取状态。条目包含不透明的原生选择 ID、名称、
具体模型 / 档位 / 自动路由类型、选择支持状态、访问证据及可选计费信息。
同名模型经不同平台执行时保留不同身份和不同费用，不按显示名称合并。

访问证据区分「上游账号目录返回」「CLI 返回的未确认候选」「此前运行
成功」和「明确不可用」；此前成功不是永久授权，价格存在也不是执行成功。

### 计费语义

按本次 CLI / 原生模型查询实际返回的数据保存以下可选维度，不要求每种
Agent 填齐：

- 计费方式：token 单价、Credits 倍率、按次、订阅包含或未提供。
- 金额及币种、计量单位、输入 / 输出 / 缓存维度；倍率及其基准。
- 免费状态及适用条件。订阅包含用量和剩余额度不能标成模型永久免费。
- 优惠后的价格或倍率、说明、生效和结束时间、适用套餐及参数条件。
- 信息来源（CLI 查询 / CLI 原生协议 / 非 CLI Agent 的账号接口）、返回的新鲜度
  证据（若有）、来源类型及采集时间。

保留上游已给出的有效倍率，不重复乘以优惠系数。未知字段使用未提供而非零。
优惠到期后停止显示为有效优惠；若无法确定新价格，显示需要刷新，不能把
旧优惠价格当现价。CLI 没有返回倍率或优惠时显示「CLI 未提供」，不从平台
文件、官方网页或公共价格目录推测补齐。CLI 返回值也不冒充最终账单金额。

### 刷新与错误

每次进入账号模型区域、选择账号、切换项目、改选模型和开始执行前，都触发
新的 CLI / 原生模型查询。没有五分钟缓存直接命中的执行路径，不设置常驻
轮询或后台模型推理。同一账号和上下文中仍在进行的并发查询可以合并，但
已经完成的历史结果不能替代发布前的新查询。失败保留最后成功快照及错误
状态供查看，阻止本次新任务启动并允许重试。

目录内容版本在选择身份、可用性或有效计费条件变化时更新。默认模型修改
另外受配置 revision 控制。账号环境或项目配置变化使对应缓存失效；网页不
暴露私有配置路径。上游在原生客户端切换账号后，依靠后续目录刷新和执行
时校验发现变化，不声称未暴露账号身份的接口可以保证识别每次外部登录变化。

## 默认模型与执行绑定

默认值继续使用 `settings.model`，兼容已有配置。新 UI 的默认模型保存要求
模型在刚查询的目录中、适配器支持选择，并校验目录版本和配置 revision。
能够可靠识别原生默认值时可以作为初始建议；不能识别时显示「默认模型未
设置」，引导用户选择，不擅自挑第一项。

单次启动新增可选模型选择参数，贯穿 Controller → Scheduler → Adapter。
适配器按 session 保存解析后的模型；send/resume 使用原 session 的选择，
不重新读取可变账号默认值。不通过临时修改账号配置或替换共享 Adapter 实例
实现单次覆盖；同一账号两次运行可以使用不同模型。

新发布页面提交账号、模型选择 ID 和目录版本。服务端检查账号状态、目录
版本、条目、选择支持和实际执行上下文。启动前必须重新查询；模型或费用
条件变化返回冲突及新目录，保留任务输入，要求用户重新确认选择。
工作目录隔离后的有效模型配置与页面读取上下文不一致时也拒绝启动并解释原因。

Run 在启动前持久化 `modelSelection`：账号、Agent、原生模型身份、选择来源、
上下文与目录版本，以及可选价格快照。沿用现有 `Run.model` 的配置 / 运行
证据含义，不能把启动参数当作上游确认。不把两种计费体系换算成伪造的总成本。

已有未带模型选择的 HTTP、Slack 和其他调用保持现有默认行为。新页面要求
明确解析默认或本次选择；默认失效、明确无权、参数不支持时拒绝该选择，
不退回其他模型。继续同一会话维持原模型；改选模型需作为新的运行明确提交。
取消、租约、资源阻塞和 currentRunId 的既有校验继续生效。

| Agent | 当前可用依据 | 实现时必须验证 |
| --- | --- | --- |
| Qoder / Qoder CN | 当前代码使用模型列表；官方说明账号目录和 Credits 倍率 | 对应安装版本与账号输出格式、实际倍率字段及单次参数 |

| Codex | 当前执行适配器支持模型参数；官方原生协议有模型目录 | 本机版本支持的只读接口，区分缓存目录与账号授权 |
| pi / Grok / Antigravity / WorkBuddy CLI | 当前执行适配器传入模型参数 | 本机只读目录接口、账号范围、模型 ID、计费字段及真实执行 |
| ZCode / Kiro | 当前模型选择存在明确限制或参数语义疑问 | 独立验证原生模型选择能力后启用；验证前显示不支持的原因 |
| Devin / HTTP 服务 / Generic CLI | 执行渠道不同于普通模型 CLI | 只在其真实契约支持模型目录和选择时提供，禁止伪造统一能力 |

最终页面对每个已配置账号显示目录读取和单次选择的支持情况。不支持的
账号保留可见并解释原因；不能把未完成集成标为已支持。具体支持实现需要
在安装版本上取证，官方文档存在接口不代表本机版本已经有它。

## 验证与完成条件

新增回归测试覆盖：账号隔离、项目作用域、价格单位与缺失值、优惠过期、
刷新失败保留快照但阻止启动、发布前再次查询、不读取静态价格文件、CLI
价格缺失不补齐、CLI 内部缓存的标识、版本冲突、默认值持久化、单次覆盖
不改默认、同账号不同模型并发、send/resume 固定模型、不支持选择、旧调用
兼容和秘密字段过滤。

用量回归覆盖：执行期间非阻塞更新、字段部分缺失、真实零值、缓存包含关系、
零分母和未知口径、增量 / 累计快照、重复事件和重连重放、回合累计完整性、
并行任务账户归属、周期重置、reroute / attempt 隔离、过期用量展示及采集故障
不阻断执行。额度和费用不同单位必须保留；不能因缺字段构造剩余额度。

有意义的执行测试必须断言实际 CLI argv / 原生请求和 Run/session 中绑定的
模型，而不只断言 UI 文本。运行相关定向 Vitest，再执行仓库 `pnpm check`。
架构和持久化字段改变时更新 architecture；非显然约束记录 know-how。

真实验收包含账号目录刷新、设置默认值、选择另一个具体模型执行创建文件
的任务、验证模型参数/运行证据与文件产物，以及网页展示和刷新后的记录。
真实用量验收对照 harness 原生事件或只读查询，确认输入、输出、缓存和额度
字段、单位、范围及更新时机；不支持的字段明确报告未提供，不能生成假计量。
真实运行可能消耗额度，只在已获授权的账号和模型上执行；目录刷新本身不
触发推理。逐账号报告验证范围，不能用一个账号的通过代表全部 Agent。
